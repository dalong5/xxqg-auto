# 单账号运行手册

## 环境和启动

需要 Node 24、npm 和 Chrome。执行 npm ci 安装锁文件依赖，复制 .env.example 为 .env，然后 npm run dev。配置会自动从 .env 读取。

默认端口 8099；如被占用，在 .env 设置 PORT=8101。默认只监听 127.0.0.1。需要其他浏览器时配置 CHROME_PATH；这不是验证码通过的保证。

APP_SECRET 可留空，由 data/secret.key 持久化生成。不要覆盖或删除密钥。API 和 worker 必须使用相同 DATA_DIR 与密钥。

## Windows 后台运行

```powershell
powershell -NoProfile -File scripts/start-background.ps1
powershell -NoProfile -File scripts/start-background.ps1 -Stop
```

脚本使用 Windows 进程服务创建隐藏、独立进程，只识别本目录的绝对入口路径，重复启动复用现有进程，停止也只针对匹配入口。运行后必须检查 /healthz 的 worker 数和实际页面；创建进程不等于服务已就绪。该方式不设置开机自启；重启电脑后需要再次启动。

前台调试使用 npm run dev。容器配置只是部署骨架，本轮没有 Docker 环境，尚未验证构建和真实运行。容器中的 PORT 应保持 8099，与 compose 端口映射一致。

## 使用

1. 打开网站，先运行浏览器自检。
2. 生成二维码，用 APP 扫码并确认。
3. 查询当前积分，核对 APP 的进度。
4. 选择网页任务；满分项目跳过，每条完成后重新查分。
5. 出现安全验证时，在网站实时画面中亲自操作，程序随后继续回查。

网站会展示 APP 专属任务的进度，但不会自动执行趣味答题、发表观点、本地频道和运动。每周/专项入口只在当前积分清单实际提供时才尝试。

二维码过期、进程中断后挂起的登录会话会明确失败，可重新生成。即使达到账号绑定上限，也允许重新扫码同一账号；绑定新账号仍受上限约束。

## 跨天、故障与数据

日期按 UTC+8 处理。跨天后不把昨日缓存当成今日进度，需要重新查询。每次正式任务先取最新积分，上限始终从平台读取。最终回查失败时任务也会失败，不显示完成。

浏览器崩溃留下的 running 任务由 worker 心跳回收。自动恢复并不保证第三方页面、网络或验证码始终可用。连续失败请查看网页事件日志，不要盲目重复执行。

data/app.db 是 SQLite WAL 数据库。备份应停止本项目 API/worker 后复制整个 data 目录，包含密钥；不可只复制正在写入的 app.db。保留 7 天的 logins.jar 明文恢复备份和浏览器 profile 也属于凭据。

## 验证

```powershell
npm test
npm run test:smoke
```

本轮 17 项测试通过，覆盖加密、并发密钥发布、锁等待、账号额度/重登、登录过期、跨天缓存、任务失败、答错后下一题与后台启动。端到端覆盖二维码、浏览器自检、验证画面恢复、坐标校验、账号归属、历史日志和结束状态。

当天成功不能证明跨天连续运行可靠；至少还需要真实跨天、登录自然过期和重启后的长期观察。当前适合有人看守的单账号本地使用。
