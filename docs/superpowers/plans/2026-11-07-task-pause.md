# 当前账号任务暂停与继续

用户要求增加暂停按钮；沿用 Node、SQLite、独立执行器和原生页面，不改变官方计分与验证方式。

选择安全检查点暂停，关闭该任务的账号上下文后再确认 paused，释放执行名额。直接冻结整个浏览器会影响其他账号；暂停时立即重新入队会让两个执行器同时使用同账号，均不采用。

状态：queued -> paused；running -> pausing -> paused；paused -> queued（用户点击继续）。pausing 不允许继续；paused/pausing 都属于该账号未结束任务，重复提交复用，解绑禁止。平台拒绝/验证失败仍失败，不能借继续任务自动重试风险响应。失联执行器的 pausing 任务恢复成 paused，不自动执行。

1. 写隔离数据库/API/浏览器/执行器的失败回归，验证权限、排队暂停、运行暂停与资源关闭后继续、其他账号继续。
2. 在数据库统一状态转换和活跃任务范围，API 校验归属；执行器在原有安全检查点响应请求，最终完成与暂停竞争由单条 SQL 裁决。
3. 增加暂停/继续按钮与中文状态，刷新页面可恢复暂停状态；SSE 的 paused 为该次执行终态，避免日志不断重连。
4. 完整回归与端到端；保留生产正在执行的任务，待自然结束再完成执行器更新。20 名额和 BBR 保留。

限制：正在进行的页面调用需要返回后才能暂停；已获积分保留，未完成的一题/材料可能重新进入。不能承诺保存第三方页面的每一处临时输入。
