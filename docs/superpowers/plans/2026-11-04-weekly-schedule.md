# Weekly Schedule Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 已登录账号按北京时间每周七天的时间表自动运行，每天每账号最多产生一次定时任务。

**Architecture:** 在现有 SQLite 和 worker 内调度，不新增系统定时器或依赖。时间表属于访客，只作用于该访客绑定的账号；沿用现有队列、账号串行、积分回查和人工验证。

**Tech Stack:** Node 24、SQLite、Express、原生网页。

**Spec:** 用户确认周一至周日 09:00、10:00、11:00、14:00、15:00、16:00、17:00，每天一次，网页可修改。

## 行为与边界

- 网页一个时间表和开关，适用于当前浏览器绑定的所有账号，包括以后扫码添加的账号；其他访客默认关闭。
- 自动执行签到、阅读、视听、每日答题；未实现的 APP 任务不计入。
- 时间按 Asia/Shanghai，程序按 UTC+8 计算，与服务器时区无关。
- 新启用时已错过当天时刻，从次日开始；运行中离线错过时刻，当天恢复后补一次，不补往日任务。
- 定时记录和任务在同一事务创建，多个 worker/重启不会重复；账号忙时稍后重新检查。
- 已排队的定时任务跨天后失效，避免恢复时积压执行；关闭开关只停止新增任务。
- 定时任务最终失败，或任意任务遇到平台风险/登录失效，该账号暂停定时，显示中文原因，重新扫码后恢复；其他账号继续。
- 网页关闭不影响 worker；本地电脑关机仍不能运行。服务器升级部署需同步源代码，当前步骤先在本地完成验证。
