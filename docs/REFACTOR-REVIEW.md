# 代码研读、根因与重构记录

2026-11-06。本轮基于 `1c75d0e`，只在本地工作区修改。业务执行器、扫码成功条件、官方接口、任务节奏、人工验证方式、数据归属和数据库表结构均保留。完整架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 功能与数据流概要

HTTP API 负责访客授权、校验和队列操作；worker 负责登录及任务调度，官方适配器负责二维码/身份/真实积分，浏览器适配器负责页面及账号上下文。SQLite 是队列、事件和缓存的持久化边界。网页读取账号快照，订阅当前任务日志；计划作用于本浏览器账号，人工验证在任务页面中完成后继续。

## 失效原理与边界

### 浏览器生命周期

故障时序：账号甲检测无实例 → 等启动；账号乙也检测无实例 → 再启动；两者完成时覆盖同一引用。关闭时只能管理最后赋值者。修复将“正在启动”和“已经运行”作为两个明确状态；失败的启动在 finally 清空，下一次仍可正常重试。

回归覆盖：并发首次请求、启动失败后再试、启动尚未完成就关闭、旧实例迟到断开、旧实例正在被新实例替换时关闭。最后一种边界在初次修复后新增失败回归并继续修正。关闭和新任务同时被不断请求的全局停机调度不在本函数中实现，调用方仍负责先停止接任务。

### 账号绘制

旧代码即使服务端没有新数据，也无条件清空并重建节点。修复缓存的是待展示状态的序列化值，不缓存账号授权或官方请求。选择账号、账号列表、昵称、到期时间、当前分数、任务状态和账号额度任一变化都会触发绘制。

以两个隔离测试账号为样本，相同 `load()` 前后观察账号选择、身份和进度区域：修复前 MutationObserver 收到 7 条变更，修复后为 0 条。该结果不是整页性能或真实设备内存基准。

### 查询

生成 1200 条交错任务事件，按单任务读取两批各 200 条，检查首条内容、顺序、游标和 SQLite 查询计划。现有实现直接通过；未为了“优化”重复建索引或改查询语义。

## 验证与证据

新增回归先运行：独立 HTTP 应用缺失、三个浏览器生命周期缺陷、重复绘制共 5 项失败；事件索引检查本来通过。随后修复，定向 17 项通过。补充“替换启动期间关闭”的边界，观察其失败，再修复至 5 项生命周期回归通过。

最终验证：`npm test` 42/42 通过，0 失败、0 跳过；`node test/flow.smoke.mjs` 通过官方二维码渲染、登录页浏览器自检，以及自建验证夹具的输入转发/隔离/恢复回归。`git diff --check` 退出码 0。另用脚本比较原 server.js 路由段和新 app.js，确认除导出外代码完全一致。

所有测试使用临时数据目录；浏览器生命周期测试模拟启动器，不操作真实学习账号或真实验证码。没有测量真实服务器的 CPU/RSS/吞吐量，不声称已达某一容量或延迟 SLA。独立代码审查未发现本轮范围内的可操作问题；审查者另行运行 16 项定向测试通过，未代替真实账号或生产负载验收。

## 重构顺序与扩容

本轮只处理资源所有权、HTTP 入口和无效绘制，既不迁移数据，也不新增抽象框架。下一轮按上述安全/一致性风险补回归和修复；容量压力出现后再测量 SQLite 写锁、事件积压、浏览器上下文和慢客户端，依次考虑共享存储与多服务器队列。扩容方案不是本轮已经实现的功能。
