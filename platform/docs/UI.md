# UI 架构

无框架、无构建：`web/index.html` + `web/styles.css` + `web/app.js`（ES module）。
理由：MVP 只有一个页面和几个弹层，引入 React/Vite 的收益（组件复用、生态）不如「零构建、秒开、可直接丢 CDN」的成本优势；接口契约 `/api/v1` 不变，将来迁 Next.js 也不用动后端。

## 2. 状态管理

`state = { me, sse, loginSse }`，全部来自 `GET /api/v1/me`。

```
refresh()  ──▶ GET /me ──▶ render()
                    ▲            │
                    │            ├─ 账号卡按钮 → 调接口 → openLog(jobId)
                    │            └─ 20s 定时静默刷新（覆盖分数变化）
                    │
            SSE(done) ───────────┘
```

原则：
- **服务端是唯一真相**。前端不猜分数、不本地累加，只渲染 `/me` 的返回。
- 局部更新靠 SSE；整体刷新靠 20s 轮询兜底（SSE 断了也不会看到过期数据）。

## 3. 实时通道

| 场景 | 通道 | 事件 |
| --- | --- | --- |
| 扫码进度 | `GET /accounts/login/:sid/events` | `status` → `waiting/scanned/done/expired` |
| 任务日志 | `GET /jobs/:id/events` | `log`（增量）、`done`（终态） |

前端用原生 `EventSource`；`done` 后主动 `close()`，避免无意义重连。

断线重连：作业 SSE 支持 `?after=<seq>`，重连时补齐，不重复不乱序。

---

## 4. 交互约定

| 操作 | 反馈 |
| --- | --- |
| 开始任务 | 按钮置灰 → 打开日志面板 → SSE 逐行追加 → 结束自动刷新分数 |
| 扫码 | 弹层 + 二维码；`scanned` 文案变「已扫码，请在手机上确认」 |
| 设定时 | `prompt` 输入 `HH:MM`，空=取消；服务端校验，客户端只展示结果 |
| 删除账号 | `confirm` 二次确认 |
| 错误 | 内联 `.msg` 或 `alert(message)`；不在控制台静默 |

---

## 5. 可访问性与响应式

- 断点：`grid-template-columns: repeat(auto-fill, minmax(330px, 1fr))`，手机单列。
- 颜色对比：正文 `#e6edf7` on `#0b1220`（AAA）；状态色只做辅助，不单独承载信息（同时有文字「正常/需重新登录」）。
- 动效：仅 `:active` 位移 1px 与 hover 背景，无入场动画（避免低端机掉帧）。

---

## 6. 文件职责

| 文件 | 职责 |
| --- | --- |
| `index.html` | 骨架 + 语义结构（不写内联样式/脚本） |
| `styles.css` | 设计 token（`--brand/--panel/--line`）+ 组件样式 |
| `app.js` | `api()` 封装、`render()`、`card()`、SSE 订阅、扫码流程 |

代码约定：
- 所有插值走 `escapeHtml`（防 XSS，日志/昵称来自外部）。
- 网络错误统一 `alert`（MVP），后续可换 toast 组件。
- 不使用第三方 CDN（二维码除外，见 `renderQr`）。
